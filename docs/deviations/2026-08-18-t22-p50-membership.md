# T22 deviation record: label-independent E80 membership for P50 selection

**Recorded:** 2026-08-18, before the T22 real-data P50 ranking is emitted by this branch.

## Frozen text being amended

`configs/method_frozen_v4.yaml` describes T22 `causal_role_selection.selection_data` as E80 translated-arm, all-response, block-16 **validated score-3 outputs**. That description assumed a role-expression judge would clear the predeclared human-validation gate.

T07 subsequently failed that gate. The automatic role judge therefore cannot supply a validated score-3 population for a primary downstream selection. Using its full E80 score-3 calls anyway would turn a rejected measurement into the mechanism that chooses the causal test roles.

## T22 rule

For the primary T22 P50 ranking, output membership is changed to:

> E80 `USER_TRANSLATED_LU`, block 16, `ALL_RESPONSE_TOKENS`, technically valid outputs with the required all-response pool present; no automatic role-score filter.

All other T22 choices remain fixed:

- score each eligible role by `(mu_role - mean_over_eligible_roles(mu_role)) dot unit(v_E80)`;
- larger score is more Assistant-side;
- exclude the literal `assistant` role;
- break exact ties lexicographically by stable role ID;
- select exactly 50;
- use no causal outcome when selecting P50;
- **require** the frozen P50 to be excluded from the held-out Axis used to evaluate those roles.

The last item is a downstream requirement, not a fact T22 can verify. T22 therefore records `p50_must_be_excluded_from_t24_heldout_axis: true` and `verified_by_t22: false`; T24/T25 must verify the exclusion where the held-out Axis is actually constructed.

## Machine-readable registration and P50 hash binding

This document fixes the membership decision before the P50 ranking is produced, but the final freeze is not complete until two V4 actions are committed together:

1. append this decision to `configs/method_frozen_v4.yaml -> deviation_records` as `DEV-2026-08-18-T22-01`;
2. fill the explicitly allowed-later `causal_role_selection.P50_manifest_sha256` with the SHA-256 of the **actual** emitted `design/causal_P50_assistant_proximal.json`.

`tools/run_t22_p50.py --finalize-method-succession` performs those two actions as one SHA succession after the real manifest hash exists. The succession also rebinds only the four forward-looking V4 pins documented in `METHOD_FREEZE_V4_13_AUG.md`. Historical provenance stamps are never rewritten.

A candidate run without `--finalize-method-succession` is marked `CANDIDATE_NOT_METHOD_BOUND`; it is not a frozen P50 and cannot open the downstream frozen causal-units gate.

## Why this is recorded now

The E80 score-3 versus all-valid bridge already shows that membership choice can materially change the estimated direction, so the two constructions must not be silently treated as equivalent. This record therefore fixes the T22 membership **before the P50 role ranking/list is generated by this branch**.

## Claim boundary

The resulting P50 remains a target-model-specific adaptation of Lu et al.'s published Assistant-proximal selection procedure. It is not Lu et al.'s unreleased exact role list, and it is not a behaviorally verified set of successful role enactments.
