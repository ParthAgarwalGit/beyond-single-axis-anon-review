# T15/T16 - confirmatory split-half Axis reliability

**Status:** completed on 2026-08-18.

PR #44 (`Deviation record: label-independent confirmatory membership`) is already merged and is the change-control authority for the primary C80 membership rule used here.

## Primary analysis

The primary C80 geometry uses:

- model arm: `USER_TRANSLATED_LU`
- pool: `ALL_RESPONSE_TOKENS`
- block index: 16
- membership: `label_independent_technical_validity`
- per-block role threshold: >=10 technically eligible outputs

The reduction streams the already-extracted T12 activations and builds C80-A and C80-B role means independently. No model rerun is required.

Observed eligibility:

- C80-A: 21,998 technically eligible outputs, 275 roles
- C80-B: 22,000 technically eligible outputs, 275 roles
- retained intersection: 275/275 roles
- C80-A default valid fractions: `{0: 0.9875, 1: 0.9875, 2: 0.9875, 3: 1.0, 4: 1.0}`
- C80-B default valid fractions: all five conditions = 1.0

The primary statistic is cross-axis same-role Pearson correlation: C80-A role means are projected on the independently built C80-B Axis, and C80-B role means are projected on the independently built C80-A Axis.

## Confirmatory result

`confirmatory_reliability.json` is the canonical in-repo record generated by `tools/run_t15_confirmatory.py` from the archived bundle. It is stamped with the source git state, active config SHA, bundle SHA-256, counts SHA-256, both T12 manifest SHA-256 values, and the immutable HF revision from which the analysed bundle was fetched.

- cross-axis Pearson r = **0.976528** over 275 roles
- 95% bootstrap CI = **[0.971010, 0.981079]** (2,000 replicates)
- Spearman rho = **0.975928**
- cosine between independently built Axes = **0.912713**
- same-axis projection Pearson r = **0.975918**
- leave-one-role-out range = **[0.975671, 0.977177]**

Frozen nulls (5,000 draws each):

- role-correspondence permutation: mean -0.000471, 95th percentile 0.099511, **0/5,000 draws >= observed**
- common-orientation sign-flip: mean 0.964840, 95th percentile 0.984195, `p_ge_observed = 0.3784` (**not separated**)
- isotropic random direction: mean 0.003313, 95th percentile 0.356251, **0/5,000 draws >= observed**

For manuscript reporting, do not write the two Monte Carlo results as literal `p = 0`; report them as 0 of 5,000 null draws reaching the observed statistic (or use a separately declared +1 Monte Carlo convention).

### Provenance boundary

The canonical historical reduction was produced before the reducer itself required an immutable HF revision, so `reduce_side_hf_revision` is intentionally `null`; it is not backfilled. The exact analysed bundle bytes are nevertheless pinned by `bundle_fetched_at_hf_revision = e1885e0865d1e6d7a39a9c2585b224b30e28b3f1` together with the bundle/counts SHA-256 values and the two T12 manifest SHA-256 values.

All future reductions fail closed unless `HF_REVISION` is set to an immutable revision, and all future analysis runs require `--bundle-revision` to be a 40-hex HF commit SHA.

## E80 membership bridge (sensitivity only)

The predeclared E80 bridge compares the archived score-3 construction with the label-independent all-valid construction on the same 253-role set:

- `cos(v_score3, v_all_valid) = 0.785438`
- role-projection Pearson r = `0.698940`
- common roles = 253

This is a sensitivity analysis, not a confirmatory statistic. It shows that membership choice materially changes the estimated Axis and therefore must be reported as a limitation/sensitivity result. The archived E80 default arm is `USER_EXPLICIT` while the role arm is `USER_TRANSLATED_LU`; both bridge Axes use the same default mean, so the comparison is intended to isolate membership rather than estimate a prompt-arm effect.

The committed `e80_membership_bridge.json` predates the final provenance-stamping cleanup. Its numerical result is retained as the predeclared sensitivity result, but it should not be represented as having the same provenance completeness as the canonical C80 confirmatory record unless it is rerun from the archived E80 tensors with a pinned HF revision.

## Claim scope

The C80 result supports **highly reproducible prompt-conditioned role geometry across independent question blocks** under the preregistered label-independent membership rule. It does **not** establish behaviourally verified role enactment, and the observed cross-axis correlation does not exceed the common-orientation sign-flip reference, so it should not be described as uniquely identifying a privileged one-dimensional orientation.

## Uncertainty implementation notes

The reported 2,000-replicate bootstrap and leave-one-role-out analyses resample the already-computed cross-projections; they do **not** rebuild the two Axes inside every resample. This is the implemented estimand and must be stated if these intervals are described in the manuscript.

The frozen `repeated_frozen_question_resplits: 300` component is now implemented and reported (`results/t15/t15_t16_resplit_results.json`, spec in `docs/DEVIATION_2026-08-25_T15_T16_RESPLIT_SPEC.md`). For each of 300 outcome-blind, provenance-derived 80/80 partitions of the pooled 160-question C80 universe, role means and the default mean are rebuilt from scratch restricted to that partition's questions, and the cross-axis same-role Pearson r and Axis cosine are recomputed exactly as in the headline confirmatory statistic — this is a genuine rebuild, not a resample of the already-computed cross-projections (contrast with the bootstrap/LOO note above).

The observed C80-A/C80-B split's statistic (r = 0.976528) is reproduced exactly by this independent pipeline and sits at the 84th percentile of the 300-draw distribution (median r = 0.972914, range [0.956277, 0.983534], std = 0.005135) — unremarkable relative to a random balanced resplit, not an outlier the construction rule happened to favor. The result held across all 300 sampled balanced partitions, and the observed split was not unusual within that sampled distribution; this is evidence against the particular deterministic split T02 constructs being an artifact, not a claim about the full combinatorial space of 80/80 partitions, which 300 draws do not exhaust.

## Reproduction

1. Run `tools/gpu_cells/t15_confirmatory_reduce.py` with an explicit immutable `HF_REVISION` to pool the existing T12 activation shards into `t15_confirmatory_bundle.npz` and `t15_confirmatory_bundle.counts.json`.
2. Download those two files at the same immutable HF dataset revision and run:

   ```bash
   python tools/run_t15_confirmatory.py analyze \
     --bundle t15_confirmatory_bundle.npz \
     --counts t15_confirmatory_bundle.counts.json \
     --bundle-revision <40-hex-hf-revision> \
     --out results/t15/confirmatory_reliability.json
   ```

The analyzer rejects missing, branch-name, short, or otherwise non-immutable revision identifiers.
